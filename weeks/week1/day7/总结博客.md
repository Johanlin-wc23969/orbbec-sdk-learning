# 总结博客

### auto & decltype
auto 和 decltype 的主要区别在于声明的数据类型。虽然他们的主要目的都是自动推导数据的类型，但是在面对引用的数据类型，auto推导出的是该数据的原始类型也就是引用背后的类型而非引用类型本身。而decltype则是推导该引用本身的数据类型，也就是引用类型。我们可以把auto理解成获取数据的原始类型，如果想要在获取数据的时候避免拷贝，需要自己手动添加引用&。而decltype可以理解成字面意思，declare（声明）type（类型），所见即所得，数据是引用类型推导出来就是引用类型。
举个例子：
```cpp
int x = 10;
int& ref = x;

auto a = ref; // int a
decltype(ref) b = ref; // int& b

```

decltype也存在特殊的使用情况，当我们对表达式使用decltype，也就是将变量用括号包裹比如decltype((x))，即使x本身是int类型，我们得到的也是引用类型。这种情况我们可以这么理解：当括号包裹变量本身，这个变量就被视作独立的表达式，一个有自己地址的资源对象，此时decltype推导出的就是引用类型，表示独立对象资源。如果我们在表达式的基础上再加上运算形成新的表达式，那么我们把它视作一个新的数值（运算出来的答案），这个时候他就是一个右值而不是一个拥有独立资源的对象，所以最终推导出来的是int类型而非引用类型。
举个例子：
```cpp
int x = 10;

decltype((x)) c = x; // int& c;
decltype((x+1)) d = x; // int d;
```

### NULL & nullptr
过去我们通常使用NULL表示空指针和空值，但是在某些场景下，空指针是被视为正常情况，比如初始化的空指针，而这种情况不视为整数0，但是NULL本事代表整数数值0，所以在C++11引入了nullptr表示空指针的情况，提供了更加细分的概念根据类型（数值和指针）。

### Function Object & Lambda 
为了方便STL容器的使用，C++提供了algorithm算法库，里面实现了通用的常见算法。为了满足日常使用，算法函数采用热插拔模式，允许程序员设置算法规则，比如排序算法sort()，可以设置降序还是升序，通过传入函数对象或者匿名函数定义规则。

在最初是不存在lambda匿名函数的，而是使用函数对象来设置算法规则，程序员需要在全局声明一个新的class，并且重载()符号，在重载的函数里定义算法规则，然后在把这个函数比如myclass()传入sort()。但是这种方式非常麻烦，每次使用algorithm的算法函数都需要定义一个类并且重载()。于是为了方便开发，C++11引入了匿名函数lambda（语法糖版的函数对象）代替传统的函数对象。从此程序员在使用算法库的时候不需要费时费力的定义class和重载()，而是直接在sort()里直接定义匿名函数。

下面对比一下两个方法：

* 函数对象
```cpp
class myclass(){
public:
    bool operator()(const int& a, const int& b){
        return a > b;
    }
}
sort(vec.begin(),vec.end(),myclass());
```
* 匿名函数
```cpp
sort(vec.begin(),vec.end(),[](const int& a, const int& b){ return a > b;})
```

### unique_ptr & shared_ptr & weak_ptr
C++内存管理一向是非常重要的，在大型项目中，常常因为忘记释放内存导致内存泄漏一系列的问题。为了解决这个问题，采用RAII风格对数据内存进行自动管理，在超出作用域的时候自动调用析构函数释放内存。这样就不要求程序员手动delete()释放内存，从而避免了内存泄漏的问题。而这个RAII风格的自动化管理叫做智能指针，一共分为三种unique_ptr,shared_ptr and weak_ptr. 

* unique_ptr
  该指针通过make_unique<Myclass>(构造参数)声明实例，只允许同时存在一个指针对象，称为独占指针。他的拷贝构造和拷贝复制都被禁用了，只允许移动构造和移动赋值。这确保了唯一的资源拥有权。

* shared_ptr
 该指针通过make_shared<Myclass>(构造函数)声明首个实例，允许同时存在多个指针对象，每个复制的共享指针不能通过make_shared<>()，而是通过等号赋值的方式创建。同一个资源的共享指针共同维护了一个计数器，记录着当前存活的共享指针。当某个共享指针被销毁，相应的计数器就会减少。只有当计数器为零，才会释放该资源的内存。

* weak_ptr
 该指针通过对共享指针对象等号进行赋值，他的目的是为了解决两个shared_ptr内部拥有对方的共享指针变量导致的循环引用的问题。通过将内部的shared_ptr转换成weak_ptr（不计入计数器）来防止计数器无法为零的困境，导致内存泄漏。weak_ptr的使用场景可以被视为当对象不影响内部成员生命周期的情况。比如一个服务器维护并包含了多个在线用户，用户的状态不应该依赖服务器本身，因此用户在服务器类内部属于weak_ptr，这样当用户处于离线状态，用户的资源会被释放，而不会因为服务器没有被销毁而导致用户的计数器无法为零。在这种情况下，用户资源被释放，服务器通过user.lock()可以随时查看用户指针是否为空指针来判断是否资源被释放（是否离线）

 ### move semantic & rvalue
 在C++存在左值和右值，左值是有地址的对象，右值是数值形式存在的临时对象。在实际开发中，常常涉及到数据的转移，而转移会将一个数据复制拷贝到另一个变量，这导致包含大量数据的对象的转移会带来不必要的拷贝开销，因此保留拷贝的同时提供转移资源拥有权的功能，C++通过左值/右值引用来区分拷贝和移动。右值的表示主要有两种形式：临时数值或者std::move()强制左值转换成右值。当实现了移动构造/赋值，参数以右值形式传进来则会触发移动构造/赋值，将资源拥有权从原指针转移到新指针，并将原指针置空，实现数据拥有权的转移。
 举个例子：
```cpp
std::vector<std::string> name = {"johan","oiyh","khks"...}
auto new_name = std::move(name); 
```

### perfect forwarding
当同时存在拷贝和移动语义，我们需要通过参数的类型去判断调用移动还是拷贝操作，在大部分情况下我们使用万能引用T&&定义参数类型（能够接受左值和右值作为参数）。然而在中转函数中，参数即使在第一次传入的时候以右值引用的类型传进来，在到达中转函数作为参数时，会被转换为左值对象，此时就需要std::forward来恢复参数的原始类型（右值）。
举个例子：
```cpp
template<typename T>
void func(T&& arg){
    wrapper(std::forward<T>(arg))
}
```
