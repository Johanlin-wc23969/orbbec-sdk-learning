# perfect forwarding
包装函数会将临时对象在转发过程中转换成左值对象，导致丢失了原本的右值状态。

因此需要完美转发在过程中保留原始右值状态，确保最终参数是作为右值传递。

完美转发实现了自动区分左值/右值参数并且确保转发过程中类型不转变。

换句话说：用一个模板同时代替无数个“左值版本+右值版本+多参数版本”的重载。

### Forwarding reference T&& 和 std::forward
```cpp
template<typename T>
void wrapper(T&& arg){
    print(std::forward<T>(arg));
}
```
传递左值
```cpp
wrapper("hello"); //传递左值参数
print(arg) // 到手就是左值
```
传递右值
```cpp
wrapper(std::string("hello")); //传递右值参数
// 原本这里会导致右值复制到arg变成左值，但是forward保留了原本的右值状态
print(arg) // 到手就是右值
```
### std::forward 做了什么
```cpp 
static_cast<T&&>(arg)
```

### push_back vs emplace_back （内部都实现了完美转发 可以根据参数左值右值类型来执行拷贝或移动）
push_back: 接受对象
```cpp
vec.push_back(std::string("johan"));
// 构造临时string
// ↓
// 移动到vector
// ↓
// 销毁临时string
```
emplace_back:接受对象和参数
```cpp
vec.emplace_back(”johan“);
// vec.emplace_back(s);               // T对象
// vec.emplace_back(std::move(s));    // T对象
// vec.emplace_back("hello");         // 构造参数
// vec.emplace_back(10, 'A');         // 构造参数
```

### perfect forwarding 的多参数类型
```cpp
template<typename... Args> // 多类型参数包
void f(Args&&... args) // 多函数参数包
{
    g(std::forward<Args>(args)...); // 展开参数包
}
```

### 左值->右值->右值引用->完美转发 链路
• 左值（lvalue）本质是可寻址的对象（有标识符），能出现在赋值运算符左侧；右值（rvalue）则是临时的、不可寻址的（如字面量、临时对象），通常作为表达式的结果存在。

• 右值引用（&&）的出现，是为了“绑定”右值，从而触发移动语义（移动构造函数、移动赋值运算符）——通过转移资源而非拷贝，避免临时对象的冗余拷贝开销，这是性能优化的核心动机。

• std::move的作用是将左值“强制转换”为右值引用（本质是告诉编译器：这个对象可以被移动，无需保留其原有状态），但它并不实际移动数据，只是改变值类别。

• 万能引用（Universal Reference，形式为T&&，需结合模板类型推导）的特殊性在于：它既能绑定左值，也能绑定右值，是实现完美转发的基础。但在转发过程中，右值引用参数在函数内部会被视为左值（因为有名称可寻址），导致原右值语义丢失。

• std::forward的作用正是“保持原有值类别”：当参数是右值时，转发为右值；是左值时，转发为左值，确保在多层函数调用中，参数的原始引用类型被正确传递到最终函数，这就是“完美转发”的核心意义——避免转发过程中值类别意外改变导致的性能损失（如本可移动却触发了拷贝）。

整个链路从区分对象的“可寻址性”（左值/右值）出发，到通过右值引用实现资源高效转移（移动语义），再到解决转发过程中的值类别保持问题（万能引用+std::forward），最终形成了一套完整的语义体系，既保证了代码的性能，也维持了类型传递的准确性。
