# unique_ptr & shared_ptr & weak_ptr
```cpp
// ✅正确做法 
std::make_unique<T>()

// ❌错误做法
std::make_unique<T>(new T)

// make_unique函数内部会自动调用new动态分配内存，括号里只传递T类的构造函数需要的参数
```

### std::unique_ptr<T>
unique_ptr 独占所有权，不允许拷贝只能移动

创建实例
```cpp
std::unique_ptr<Myclass> onlyone = std::make_unique<Myclass>();
```
转移拥有权(使用std::move触发移动构造)，拷贝构造被删除(不使用move会被编译器认为是拷贝，出现编译错误)
```cpp
std::unique_ptr<Myclass> anotherone = std::move(onlyone);
```

### std::shared_ptr<T>
shared_ptr 共享资源，引用计数

创建实例
```cpp
std::shared_ptr<Myclass> sharedone = std::make_shared<Myclass>();
```
添加共享实例 
```cpp
std::shared_ptr<Myclass> sharedanother = sharedone;
```

### std::weak_ptr<T>
weak_ptr 不计入计数，解决循环引用 (shared_ptr<A> A 和 shared_ptr<B> B 内部互相存在对方的引用)
```cpp
std::weak_ptr<Myclass> weakone = sharedone; // weak_ptr不能独立存在，必须依附一个shared-ptr管理的控制块
```

从“管理者”到“被管理者”用 shared_ptr；从“被管理者”回指“管理者”用 weak_ptr。

### 循环引用的根源
shared_ptr对象在超出作用域的时候会调用reset()减少计数器，此时会判断当前计数器是否为零，如果不为零则不会调用析构函数，因此内部shared_ptr成员不会被reset()，计数器不会减少。

对象内部成员的 shared_ptr 只有在对象析构时才会析构。而对象析构的前提是该对象自身的引用计数归零。因此如果对象自身引用计数永远大于 0，那么它内部持有的 shared_ptr 永远没有机会析构，从而也永远无法降低其它对象的引用计数。
