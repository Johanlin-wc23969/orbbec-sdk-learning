# std::optional
用来表示一个值存在，也可能不存在的情况
使用场景：接受任何类型，本质只是将数值外面包装了一层
所以只要遇到需要判断是否返回有效结果的情况，在函数返回类型改成std::optional<T>就行

### -1 和 std::optional
在返回整数类型的函数中，如果表示数值不存在，而函数要求返回值，我们通常用-1代替。但是对于其他类型比如字符串，自定义类等等无法用-1来表示不存在，因此引入了std::optional。或者说没有明切的空值表示，毕竟-1也可能是有效数值。

* -1 返回值
```cpp
int getScore(std::string name){
    if(name == "Johan"){
        return 12;
    }
    else return -1;
}
```
* std::optional
```cpp
std::optional<int> getScore(std::string name){
    if(name == "Johan"){
        return 12;
    }
    else return std::nullopt;
}
```

### std::optional 创建
* 有值
```cpp
std::optinal<int> opt_value = 12;
```
* 空值
```cpp
std::optinal<int> opt_value = std::nullopt;
```

### std::optional 获取值
std::optional<int> age = 10;
* 解引用
```cpp
std::cout << *age << std::endl;
```
* value()
```cpp
if(age){
    std::cout << age.value() << std::endl;
}
```

### std::optional 提供默认值 value_or()
std::optional<int> age = 10;
std::cout << age.value_or(0) // 如果是空值输出0 否则正常输出

### 实际案例
案例1:
```cpp
auto config = getConfig("port");

// 检查是否有效, 语义清晰（比传统的空字符串或者-1要更直观）
if (config)
{
    use(*config);
}
else
{
    std::cout << "未找到匹配config\n";
}

// 清空内容
config.reset() // 置空 std::nullopt
config.has_value() // false
```

案例2:
```cpp
struct User
{
    std::string name;

    std::optional<std::string> phone;
};
```

### 为什么phone需要std::optional，而name不需要？
因为phone不是强制要求的，可以为空。对于使用了optional的数值在实际业务中需要判断是否为空。而name强制要求有数值的不需要额外的判断。
判断是否该用 optional 的黄金准则

问自己一句话：

“值不存在，是否是业务上的正常情况？”

如果答案是：是

那么考虑：

std::optional<T>

例如：

查找用户
查询缓存
读取配置
解析输入
数据库查询

如果答案是：否

那么不要用。

例如：

人的姓名
订单编号
学生学号
商品价格

这些本来就应该存在。
